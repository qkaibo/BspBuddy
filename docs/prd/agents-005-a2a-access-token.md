## 概述

为外部 IDE（Cursor 等）或其他 A2A 客户端提供**用户级接入凭证**：登录 BspBuddy 后，在独立的「A2A 接入」界面签发、复制、查看与吊销 Token，再用 `Authorization: Bearer <token>` 调用本机/局域网后端的 `/a2a/*` 端点，连接当前用户租户下的专家能力。

本能力解决「协议已通、凭证无处申请」的断点；**不**挂在技能商店，也**不**替代 `skills-003` 的 Agent 技能 Runtime Token 产品语义（商店「开发者 → 签发 Agent Token」入口不得作为 A2A 接入主路径）。

类型约定：

| 名称 | 含义 |
|------|------|
| **A2A 接入 Token** | 绑定**当前后端用户**的个人访问令牌；用于外部客户端调用 `/a2a/*` |
| **会话登录 Token** | `POST /api/auth/login` 返回的短期会话凭证（默认 14 天）；可临时调试，**不是**本 PRD 的主交付物 |
| **技能 Runtime Token** | `skills-003` / 商店签发的 Agent 技能凭证；产品入口与文案属于技能域 |

## 用户场景

| 角色 | 场景 | 动机 |
|------|------|------|
| 桌面用户 / 工程师 | 登录 BspBuddy → 设置里打开「A2A 接入」→ 签发 Token → 粘贴到 IDE 配置 | 用 IDE 通过 A2A 调用本机 BspBuddy 专家，无需在对话里粘贴密码 |
| 桌面用户 / 工程师 | 换电脑或怀疑泄露 → 在列表里吊销旧 Token → 重新签发 | 可撤销、可轮换，不依赖改密码 |
| 桌面用户 / 工程师 | 查看 Base URL、示例请求头与发现端点 | 一次配置成功，减少「端口/鉴权」试错 |
| 安全意识用户 | Token 明文只在签发瞬间可见一次；列表只显示掩码与设备名 | 降低凭证落盘到截图/聊天记录的风险 |

## 功能清单

| # | 功能 | 关联页面 | 说明 |
|---|------|---------|------|
| 1 | 展示接入信息 | 设置 → A2A 接入 | 显示当前可用的 A2A Base URL、健康检查提示、当前用户身份摘要 |
| 2 | 签发 Token | 同上 | 填写设备备注 + 有效期 → 签发 → **明文仅展示一次**并支持一键复制 |
| 3 | Token 列表 | 同上 | 展示当前用户的 Token（含已吊销/已过期）；掩码、备注、过期时间 |
| 4 | 吊销 Token | 列表行操作 | 立即失效；后续带该明文的请求返回 401；行仍保留便于审计 |
| 5 | 删除 Token | 列表行操作（已吊销 / 已过期） | 从列表与库中**永久删除**该条记录；不可恢复 |
| 6 | 接入说明（只读） | 同上 | 固定说明：Header、发现列表、任务委托路径；可复制示例 curl（不含真实 token） |
| 7 | 未就绪态 | 同上 | 后端未启动 / 未拿到后端用户身份时，给出明确错误与重试，禁止空列表假成功 |

**明确不做（首期）**

| 不做 | 原因 |
|------|------|
| 全局 / 租户级共享一把 Token | A2A 鉴权按用户隔离；共享密钥无法表达 `user_id` / 租户边界 |
| 把入口放在技能商店「开发者」菜单 | 产品域错误；易与 `skills-003` 混淆 |
| 在 UI 常驻展示登录会话 JWT 全文 | 会话 Token 可调试用，但不是 A2A 产品主路径；避免误当长期密钥 |
| 首期多租户跨端云签发门户 | 以桌面连本机/局域网后端为主；云端形态后置 |

## 数据模型

首期**复用**已有表 `agent_skill_tokens`（模型 `AgentSkillToken`），通过用途字段与技能 Runtime 区分；不新建平行鉴权体系。明文仍只在创建响应返回一次，库内只存 hash。

### AgentSkillToken（已有，扩展用途）

| 字段 | 类型 | 必填 | 来源 | 说明 |
|------|------|------|------|------|
| id | string | 是 | `AgentSkillToken.id` | 主键，前缀 `agtok` |
| tenant_id | string | 是 | 当前后端用户 | 租户隔离 |
| user_id | string | 是 | 当前后端用户 | Token 归属用户；A2A 请求身份由此解析 |
| token_hash | string | 是 | 明文 SHA-256 | 永不回存明文 |
| device_label | string | 否 | 签发表单 | 设备/用途备注，如 `cursor-ide`；列表展示 |
| expires_at | datetime | 是 | 签发表单 TTL | 过期后鉴权失败 |
| revoked_at | datetime | 否 | 吊销操作 | 非空即失效 |
| created_at | datetime | 是 | 服务端 | 创建时间 |
| **purpose** | string | 是 | **新增** | `a2a` \| `skill_runtime`；本 PRD 签发固定写 `a2a`。缺省历史行按 `skill_runtime` 回填 |

### 明文 Token 约定

| 项 | 约定 |
|----|------|
| 前缀 | A2A 用途建议 `bba2a_`（与 `bbsk_` 技能 Runtime 区分）；鉴权层须同时接受该前缀 |
| 形态 | `{prefix}{urlsafe_random}`；仅创建接口返回一次 |
| 鉴权 | `Authorization: Bearer <明文>` → `get_current_user` 解析为对应用户 |
| 权限范围 | 与对应用户登录后一致：仅本 `tenant_id` 下 active 专家的 A2A 发现与委托 |

### 接入配置（只读展示，非持久化实体）

| 字段 | 类型 | 来源 | 说明 |
|------|------|------|------|
| base_url | string | 主进程 FastAPI bridge / 网络配置 | 如 `http://127.0.0.1:52020` |
| agents_url | string | `base_url + /a2a/agents` | 发现列表 |
| health_url | string | `base_url + /api/health` | 连通性自检 |

#### 交互链

- 进入页面 → 拉健康检查 + `/api/auth/me` + Token 列表 → 渲染接入信息  
- 点击 [签发并复制] → 校验备注非空 → `POST` 签发（`purpose=a2a`）→ 展示明文一次 → 写入剪贴板 → Toast「已复制，仅显示一次」→ 刷新列表  
- 点击 [吊销] → 确认 → `DELETE`（软吊销）→ Toast → 刷新列表；该明文立即不可用  
- 点击 [删除]（仅已吊销 / 已过期）→ 确认 → `DELETE?permanent=true` → Toast → 行从列表消失  
- 点击 [复制示例] → 复制不含真实 token 的 curl / Header 模板  
- 后端未就绪 → 错误态文案 + [重试]；签发按钮 disabled  

#### 按钮权限

| 按钮 | 显示 / 可用条件 |
|------|----------------|
| 签发并复制 | 后端就绪且已解析到后端用户 |
| 吊销 | 列表项属于当前用户且 `revoked_at` 为空且未过期 |
| 删除 | 列表项属于当前用户且（已吊销 **或** 已过期） |
| 复制 Base URL / 示例 | 始终可用（示例在未就绪时可仍复制模板） |

## API 依赖

| 端点 | 方法 | 触发场景 | 说明 |
|------|------|---------|------|
| `/api/health` | GET | 进入页 / 重试 | 后端就绪 |
| `/api/auth/me` | GET | 进入页 | 展示当前后端用户（需 Bearer） |
| `/api/enterprise/agent-tokens` | POST | 签发 | body：`device_label`, `ttl_hours`, **`purpose: "a2a"`**；响应含一次性 `token` |
| `/api/enterprise/agent-tokens` | GET | 进入页 / 签发后刷新 | **仅返回当前用户**且建议支持 `purpose=a2a` 过滤；无明文 |
| `/api/enterprise/agent-tokens/{token_id}` | DELETE | 吊销 | 默认写 `revoked_at` |
| `/api/enterprise/agent-tokens/{token_id}?permanent=true` | DELETE | 永久删除 | 从库删除行；用于清理已吊销/已过期 |
| `/a2a/agents` | GET | IDE 侧（本页可用「测试连接」可选） | 验证 Token 可用 |
| `/a2a/agents/{agent_id}/tasks` | POST | IDE 侧 | SSE 委托；本页不强制测任务 |

### 鉴权与实现约束（产品要求）

1. A2A 三个端点继续依赖 `get_current_user`；接入 Token 必须能解析为真实 `User`。  
2. 若引入 `bba2a_` 前缀，鉴权 fallback 须与 `bbsk_` 同等处理（查 `AgentSkillToken`）。  
3. 列表接口不得返回明文；创建接口明文只出现在响应 body 一次。  
4. **桌面本地 Phase1 会话**（`auth-service` 的 `local.*`）不能直接当 A2A Bearer；签发必须走 FastAPI 已认证用户（当前桥接自动登录或后续统一登录）。UI 须明示「后端身份」，避免用户以为桌面切换用户等于换了 A2A 身份（在 auth 未统一前写清限制）。  

### 与 skills-003 的边界

| | A2A 接入 Token（本 PRD） | 技能 Runtime Token（skills-003） |
|--|-------------------------|----------------------------------|
| 入口 | 设置 → A2A 接入 | 技能商店 / 安装面板 |
| purpose | `a2a` | `skill_runtime` |
| 主要调用面 | `/a2a/*` | 技能 runtime / 规则安装 |
| 文案 | IDE、A2A、专家委托 | Cursor 技能壳、`.bspbuddy_skill_token` |

存储可同表；**产品入口与文案必须分离**。技能商店现有「签发 Agent Token」不得改名为本能力的唯一入口；后续可改为仅技能用途或加跳转提示。

## 页面关系

- **From:** 系统设置（`SettingsPanel`）左侧分类「A2A 接入」→ 右侧内容区（同页，不跳转子路由）  
- **To:** 无强制跳转；可选链到专家中心（了解有哪些可委托专家），不自动打开技能商店  
- **数据耦合:**  
  - 依赖后端用户身份（auth / fastapi-bridge）  
  - 签发结果影响外部 IDE 能否调用 `agents-004` 端点  
  - Agent Card 中的 `url` 依赖 `BASE_URL` 与本页展示的 Base URL 一致，否则 IDE 按 Card 回调会打错主机  

```
SettingsPanel（左分类 / 右内容）
  │
  │ 左侧选「A2A 接入」
  ▼
右侧嵌入 A2A 接入内容（本 PRD）
  │
  │ 签发 Token（purpose=a2a）
  ▼
外部 IDE 配置 Bearer
  │
  │ GET /a2a/agents · POST /a2a/agents/{id}/tasks
  ▼
agents-004 A2A 协议端点 → agent_loop
```

## 验收标准

- [ ] 登录（或后端桥接就绪）后，可在 **系统设置** 左侧选 **A2A 接入**，右侧直接签发；设置页为左右两栏；技能商店不是主入口  
- [ ] 页面展示真实 Base URL、发现端点、后端用户摘要；后端未就绪时有错误态与重试，无永久空成功  
- [ ] 可填写备注与 TTL → 签发 → 明文仅一次可见且可复制；刷新/关闭后列表无明文  
- [ ] 列表至少能看到刚签发的条目（备注 + 过期信息）；可吊销且吊销后带旧 Token 调 `/a2a/agents` 返回 401  
- [ ] 已吊销或已过期条目显示 [删除]；删除后列表不再出现该行，库中无残留  
- [ ] 使用签发的 Token：`GET {base}/a2a/agents` 返回当前租户 active 专家列表（≥0，结构正确；有专家时 ≥1）  
- [ ] 文档/页内说明含 Header 与路径；示例复制不含真实 token  
- [ ] 与 `skills-003` 入口文案不混用；同表则 `purpose` 可区分，A2A 列表默认只显示 `a2a`  
- [ ] Agent Card / 本页 Base URL 一致（或页内明确提示需配置 `BASE_URL`），避免 IDE 按 Card 连错端口  
- [ ] 合并前可演示：设置内签发 → IDE/curl 带 Token 调通 `/a2a/agents` 一条路径
