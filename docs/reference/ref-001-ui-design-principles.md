# BspBuddy UI 设计原则

本文卡住「禁止纯输入框页 / 脚手架当完成」：工程师合并前可对照验收。

布局与信息架构以 `docs/` 中对应 reference / PRD 为准。`specs/` 已废弃，勿再引用。本文只补可执行的产品 UX 硬性约束，不重复画布局。

**视觉系统**以仓库根目录 [`DESIGN.md`](../../DESIGN.md) 为准（令牌、`.bb-*` craft 原语、`PanelChrome`、侧栏密度、悬浮 Composer）。新增页面必须复用该系统，禁止另起色板或顶栏样式。

产品名统一 **BspBuddy**；参考实现 / 截图可注明来源，勿把品牌写成参考实现名。

---

## 硬性原则

1. **布局真理 = 截图 / 权威布局文档**；**视觉真理 = DESIGN.md**  
   欢迎态、侧栏、Composer 区域以 docs 布局 reference（或过渡期截图 SPEC）为准；文字推断的旧 ASCII / 三栏骨架不得当作对齐目标。观感、间距、原语类名以 `DESIGN.md` + `src/renderer/index.css` 为准。

2. **验收用户路径，不验收「有页面」**  
   合并标准是用户能走完主任务（进入 → 选/填 → 回到对话/看到结果），不是路由能打开、组件能挂载。

3. **禁止纯输入框页**  
   每个界面至少具备：有意义的空状态（含下一步指引）、一个明确主 CTA、示例或合理默认值。只有空白表单 / 空白列表 ≠ 完成。

4. **欢迎态 = Composer 一体**  
   欢迎屏必须可直接输入并发送；欢迎文案、场景/技能入口与 Composer 同屏一体，禁止「先点进对话页才能说话」。

5. **二级功能先闭环再做后台**  
   插件、技能、专家、连接器等：先保证「能进入、能选、能回到对话」，再堆完整 CRUD / 配置表单。选不了资源的后台页不得标完成。

6. **资源选择器必须可完成绑定**  
   浏览（有真实/合理 mock 数据）→ 选择 → 已选展示名称摘要 → 可移除。禁止 raw ID 输入、永久「暂无数据」、假按钮。

7. **组件 SPEC 必须写可用态**  
   新建/更新组件 SPEC 至少覆盖：`empty` / `loading` / `error` / `default`，并标明主操作；缺态不算 SPEC 齐全。

8. **控件可参考 Fluent / Ant，信息架构跟截图**  
   按钮、表单、间距可借设计系统；导航层级、欢迎区结构、Composer 位置以参考截图为准，不另起一套 IA。

9. **脚手架 ≠ 上线**  
   空 handler（`return []`）、硬编码假成功、无加载/错误态的面板，一律视为未完成，不得在 plan/README 标已完成。

10. **合并前可演示主路径**  
    PR / 合并前能在真实应用里演示一条端到端主路径（含空态与至少一次成功操作）；仅 L1 静态通过不算过关。

---

## 验收清单

- [ ] 布局/欢迎态对照权威布局文档（docs reference 或过渡期截图 SPEC），无以旧 ASCII 为准的偏差借口
- [ ] 视觉对照 `DESIGN.md`：二级面板用 `PanelChrome` / `.bb-*`，主内容偏白，少硬分割线，无另起主色
- [ ] 主路径可演示：进入 → 完成核心操作 → 回到对话或看到结果
- [ ] 界面含空状态指引、主 CTA、示例/默认值（非纯空白输入框）
- [ ] 欢迎态可直接发送，Composer 一体（悬浮 dock，非贴底整条）
- [ ] 二级功能至少「能进入、能选、能回对话」；选择器有 ≥3 条可用数据
- [ ] 组件 SPEC 含 empty/loading/error/default + 主操作
- [ ] 无永久空列表 IPC、无 raw ID 绑定、无假交互按钮
- [ ] 未把脚手架/空面板标成已完成
