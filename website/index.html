Why · 为什么是专家

同一个模型，换一套领域组织方式

通用助手什么都答一点；领域专家带着分层知识与可执行 SOP，啃的是你项目里真正难的那一类事。

专家，而非万能分身

按领域配置人设、技能与知识绑定。充电专家不会被当成通用聊天机器人。

知识在库，不在提示词里堆

基线代码、datasheet、项目 overlay 在后台知识库；对话时经 MCP 检索，可追溯引用。

工作流在你日常工具里

桌面工作台管专家与任务；IDE 通过 MCP 在编码现场问同一位专家。

Knowledge · 后台知识库

三层空间，冲突时项目说了算

领域公共经验、基线 BSP 与手册、项目私有 overlay——入库在知识库侧，专家检索时按优先级合并。

1

Project · 项目私有

overlay、DTS 改动、专属 FV / 原理图。项目间物理隔离，clarence 问不到别项配置。

最高优先
2

Baseline · 基线公共

某版 BSP 公共代码与芯片 datasheet（如 SW5100 + PM7250B）。同基线多项目共享。

次优先
3

Domain · 领域公共

跨项目 SOP、排错路径、概念说明——人沉淀的通用经验，不是某一版 BSP 私货。

兜底
搜索优先级 Project → Baseline → Domain
MCP Bridge 语义检索 · 门禁 scope · 引用回传

Mechanism · 机制

四步：从专家到可拍板的结论

你选专家、定项目上下文；检索与编排交给系统，最终决策在你手里。

选定领域专家

如充电专家。人设、SOP、技能与知识空间已绑定。

挂上当前项目

切换 project 后自动带上 Domain + Baseline + 本项目私有空间。

在桌面或 IDE 提问

同一专家、同一 MCP 知识门禁；编码现场也能召唤。

审阅引用并拍板

看见出处与成本，采纳、打回或继续追问。

Surfaces · 接入

同一专家，三种入口

无论你在工作台、编辑器还是知识控制台，专家与知识上下文保持一致。

桌面工作台

召唤专家、管理 SOP / Skill / 绑定，对话与任务编排的主入口。

IDE · Cursor MCP

在编码环境无缝协作，随时拿到专家级上下文与建议。

知识库 Console

学习、索引与三层空间管理在知识库侧；专家只消费已放行的知识。

Capabilities · 能力

你拿到的是一套可绑定的专家系统

不是提示词玩具，而是人设、流程、工具与知识可配置、可复用的工作台。

01

专家资源绑定

SOP、Skill、MCP、知识空间、模型——按专家 Scope 管理，运行时统一进 Manifest。

02

MCP 知识检索

后台知识库负责索引与隔离；对话经 MCP 带 scope 检索，引用可回传。

03

你是决策者

下达目标、看过程与出处、随时介入。专家辅助，拍板在你。

多轮对话 SOP 执行 Skill / MCP 三层知识空间 引用可见 跨会话记忆 可私有部署
